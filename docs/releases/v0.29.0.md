## v0.29.0 — User vault

_2026-09-17_

A per-user encrypted secrets store that the agent can **use but never read**.

Until now a password for a site with no OAuth, or a token for a service no plugin knows about, had one route into an agent: pasted into chat, where it stays in the transcript and every later prompt. The vault gives it a place to live and a way to be used without ever entering the model's context.

### New

- **Vault.** Portal → Vault. Add a named secret; it is stored AES-256-GCM under `ENCRYPTION_KEY`, same as OAuth tokens. Write-only from every surface — the list never carries a value, and there is no reveal. To rotate, replace.
- **`{{vault:NAME}}` in any tool call.** The reference is resolved in `executeSingle`, after the arguments leave the model and before the tool's zod schema runs, so it covers every plugin tool, `browser_*`, `files_*`, batch execution and the REST endpoint alike. Unknown name → `VAULT_SECRET_NOT_FOUND`, handler never runs.
- **Result scrubbing.** Any value substituted in a call is replaced with its reference in that call's result and error message before the model sees it, walking the result structurally (strings, matching number/boolean/null leaves, and keys). A result that can't be serialized fails closed with `VAULT_SCRUB_FAILED` instead of returning unscrubbed. Scrubbing now also covers a 10-minute recent-values window per user: a value substituted in one call is scrubbed from every later result too, so `browser_read_text` after a login, or `files_read` after a `files_write`, is covered even though that later call never itself referenced the secret. Best-effort against encodings and, under `CLUSTER_ENABLED`, against a result served by a different worker — see the docs for the limits.
- **`vault_presign` one-time URLs.** For handing a value to a script or `.env` outside workbench: a `GET` that works exactly once (DELETE-arbitrated, atomic on both backends), 120 s default TTL, `text/plain` body, route silenced in the request log.
- **`vault_list`.** Names, descriptions, last-used, and each secret's reference.
- **One-time links for values you don't want to keep.** Portal → Vault → One-time link: type a value, pick 1/5/10 minutes, get a URL — no vault entry is created. The URL returns the value exactly once, then 404; unused, it expires and the value is destroyed with it. The value lives only in the link's `pending_auth` row, encrypted under the same key, and only a portal session can mint one (`POST /api/vault/otl`; there is deliberately no tool for it). For "here is the password for this one login" without the transcript ever holding it.
- **Portal-only writes.** `PUT`/`DELETE /api/vault/:name` require a portal session; an agent's API key or OAuth token gets `403 PORTAL_SESSION_REQUIRED`, so an agent can use the vault but cannot rotate or wipe it. `GET` still works on any bearer.
- **Add / replace as pages.** `/vault/new` and `/vault/:name/replace` instead of a dialog: a back link, a reference preview that updates as you type the name, an eye toggle on the value field. The typed value lives in that page's state only and is gone on Save or Cancel.
- **Development compose.** `npm run dev:docker` (`docker-compose.dev.yml` + `Dockerfile.dev`) runs the dev servers from the mounted tree: `tsx watch` on :3001, Vite with HMR on :3000, Linux `node_modules` in anonymous volumes, polling watchers for VM-backed mounts. Vite proxies every server path (`/api`, `/mcp`, `/rest`, `/authorize`, `/token`, `/j`, `/c`, …), so `SERVER_PUBLIC_URL` is the portal origin in dev too and one registered SSO redirect URI serves prod and dev. Colima note in `deploy/docker.md`.

### Schema

New table `user_vaults` on both dialects, created on boot. Added to the SQLite→PostgreSQL migration table list.

### Fixes

- Modal kept stealing focus on every keystroke when its parent re-rendered (the vault form); the open effect now depends on `open` alone.
- Stray hairline above the note in the Files and Vault box headers (`ui-stat-note` border inside the header slot).
