## v0.33.0 — Node.js RCE fix, pentest fixes, browser domain blocklist, audit Kafka copy

A security-led release. It carries a rebuilt Docker image (below), the fixes for
all seven confirmed findings from an external black-box + source review, and two
operator features: an admin-managed browser domain blocklist and an optional
Kafka copy of the audit log. It was previously prepared as v0.32.1; the two
features make it a minor. See
[docs/findings/2026-11-01-security-report-fixes.md](../findings/2026-11-01-security-report-fixes.md)
for full technical detail on each.

Two of the seven findings chained into a complete account-compromise path:
an unauthenticated attacker could register an OAuth client with no
redirect-URI validation, get a signed-in employee's authorization code with
no consent action, then read every vault secret in plaintext through the
agent-facing `vault_presign` tool. Both halves of that chain are closed here,
along with connect-flow CSRF, an unauthenticated `/metrics`, a
redirect-following SSRF in the Google Drive upload tool, session fixation
via blind `#token=` fragment adoption, and an IPv6 unspecified-address gap in
the SSRF guard.

### Node.js 26.12.1 for the Brotli decoder RCE (CVE-2026-111497)

A security patch release. It changes nothing in workbench's own code. It rebuilds the image on a Node.js runtime that includes the [2026-10-21 Node.js security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases).

The main fix in that release is **CVE-2026-111497 (High)**, an out-of-bounds write in Node's Brotli decoder. A process that decodes attacker-controlled Brotli data can be made to leak memory or run arbitrary code. Workbench is exposed through `fetch()`, which decodes `Content-Encoding: br` responses automatically:

- **Custom apps and OAuth discovery** fetch URLs that a user supplies (`custom-apps/ssrf.ts`). The SSRF guard blocks private addresses, but a public host that the attacker controls passes. It can answer with a crafted `br` body that the server decodes.
- **Integration and curl-proxy calls** decode responses from third-party APIs. This needs a compromised or hostile upstream, so the risk is lower, but the decoder is the same.

The server process holds every user's OAuth tokens and vault secrets, so a code-execution bug in it is serious. **Self-hosted operators should upgrade.** Until the stable tag ships, pull the RC explicitly or rebuild your own image with `docker build --pull`.

The same Node release also fixes a TLS hostname check bypass for non-canonical IPv4 hosts and a `crypto.randomUUID()` / `randomInt()` entropy-cache issue. Workbench uses both APIs, and this image includes those fixes as well.

Ships as a release candidate first because it changes the Docker image.

### Features

- **Browser: admin-managed domain blocklist.** Admins set blocked domains in the admin Config tab; agent browser tabs refuse navigation to them. A strict `*.` prefix matches subdomains only. Stored in instance settings, so no schema change.
- **Browser: exceptions to the domain blocklist.** An allow list sits beside the blocklist, so `*.prod.example.com` can be blocked while `x.prod.example.com` stays reachable. When a block entry and an exception both match, the more specific one wins (more labels after any `*.`) and the exception wins a tie. An exception alone allows nothing extra and never lifts the loopback / internal-host guard. Stored as the `browser_allowed_domains` setting (no DDL); the admin PUT takes an optional `allowed` list and leaves stored exceptions alone when omitted.
- **Audit: Kafka copy of the audit log.** `AUDIT_LOG_DEST` is now a comma list (`db`, `stdout`, `kafka`; `sqlite` still works as an alias for `db`). `kafka` is a copy that always keeps `db`, sent from a bounded in-memory queue by one background producer, so tool calls never wait. Delivery is at-least-once with `event_id`. New dependency: `kafkajs`. See [findings](../findings/2026-11-04-audit-kafka-copy-and-curl-audit.md).
- **Audit: curl sessions.** `curl_session` mints (`CURL_SESSION`) and proxied requests (`CURL_REQUEST`: method and path only, no query, headers, body or error text) are now audited.

### Fixes

- **Docker: pin `node:26.12.1`.** `Dockerfile` and `Dockerfile.dev` now build from `node:26.12.1-bookworm-slim`, and `Dockerfile.sample-oauth` from `node:26.12.1-alpine`. They no longer use the floating `node:26-*` tags. With a floating tag, a build could reuse a cached, vulnerable `26` base layer and still ship the old runtime. The Dependabot `docker` updater keeps the pin current.
- **CI: Pages build on Node 22.** `pages.yml` ran on Node 20, which is end-of-life and gets no fix for this CVE. It now uses 22, matching `engines: ">=22"`.
- **OAuth: silent consent + open redirect-URI registration.** `POST /register` now restricts `redirect_uris` to https/loopback; the portal's consent page requires an explicit Approve click and names the requesting client and destination instead of auto-submitting for a signed-in session.
- **Auth: connect-flow CSRF.** Plugin OAuth and custom-app connect flows now bind to the initiating browser via a one-time cookie + nonce, so a second user can't start a connect flow and have a victim's approval land in the attacker's account.
- **Vault: agent credential could read every secret.** `vault_presign` is removed from the agent-facing tool registry. Only the portal-session-gated `POST /api/vault/otl` route can mint a one-time link.
- **Telemetry: unauthenticated `/metrics`.** Now 404s unless `METRICS_TOKEN` is configured and presented as a bearer token, on every failure path.
- **Google Drive: redirect-following SSRF.** `google_drive_upload_from_url` now follows redirects manually, re-validating the private/loopback guard on every hop, with a hop cap.
- **Portal: session fixation via `#token=` adoption.** A login-ceremony nonce, generated client-side before redirecting to SSO, now gates whether a fragment token is adopted.
- **SSRF guard: IPv6 unspecified address.** `isPrivateHost` now blocks `::`, `[::]`, and the fully-expanded zero form.
- **Test: flaky `browser-audio-tools` assertion.** A capability-token substring check could false-fail on random collision; now asserts the token value directly.
