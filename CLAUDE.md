# workbench

Self-hosted MCP tool aggregator for AI agents. Connects to SaaS tools via per-user OAuth. Extensible via plugin SDK.

## Quick Links

- **Documentation:** `docs/site/` — the published site. Markdown sources in
  `docs/site/_content/`, nav in `docs/site/nav.json`, generated by
  `node docs/site/build.mjs`. Edit and commit the Markdown only — the generated
  HTML lands in the untracked `docs/site/_site/`, and the Docs workflow rebuilds
  and publishes it on every push to main. CI runs the same build on a pull
  request, so a broken internal link fails there.
- **Findings:** `docs/findings/` — ongoing discoveries recorded here. Published
  automatically as the site's Field notes section; there is no index to update.
- **Internal history:** `docs/internal/` — superseded planning artifacts. Not
  documentation, not published.

## Architecture

Monorepo: TypeScript, Fastify + MCP SDK, React portal, SQLite or PostgreSQL.

See [docs/site/_content/start/how-it-works.md](docs/site/_content/start/how-it-works.md) for full details.

## Public Repo Hygiene

This repo is **public**. History is published too — a leak in any commit is permanent.
Before staging/committing, scrub. Never commit:

- **Personal PII** — real names, emails, phone numbers. Test fixtures use synthetic
  values only: `Test User`, `dev@example.com`, `acme`/`demo-repo`.
- **Internal/company refs** — company names, internal project/service names,
  internal hostnames, IPs, infra endpoints (k8s/CD/secrets-manager), Jira keys,
  Slack workspace IDs. Generic examples only: `example.com`, `acme`.
- **Secrets** — keys, tokens, OAuth client secrets, passwords. All secrets come from
  env vars; `.env.example` holds placeholders only. Never hardcode, even in tests
  (use obvious fakes like `gsecret`, `tok-abc`).
- **Internal-only refs in code** — RFC-1918 / `.internal` URLs are fine ONLY as SSRF
  test fixtures (asserting they get blocked).

Pre-commit check:

```bash
git diff --cached | grep -inIE '<company>|<internal-project>|@(icloud|gmail)\.com|<real-name>'
```

**No AI co-authorship.** Never add a `Co-Authored-By:` or "Generated with …" trailer naming Claude/Anthropic to commits or PRs, and never commit under an AI author identity. The `.githooks/commit-msg` hook enforces this — enable once per clone:

```bash
git config core.hooksPath .githooks
```

If publishing existing history, also purge stray blobs (e.g. committed `node_modules`)
with `git filter-repo`.

## Releases

- Every release ships a hand-written `docs/releases/<tag>.md` with decent markdown notes — group by category (Features / Fixes), explain the *why* not just the commit subject, link findings docs when relevant. The release workflow prefers this file over auto-generated git-log dumps.
- **Release candidates.** Anything touching Docker image, DB schema, auth, or proxy goes out as `vX.Y.Z-rc.N` first. The RC publishes as a GitHub pre-release (auto-detected from the `-` in the tag) so `latest` Docker tag never moves; pull it explicitly with `vX.Y.Z-rc.N`. Soak, then `scripts/promote-rc.sh vX.Y.Z-rc.N` to bump, tag, and push the stable release. Notes live under the *stable* name (`docs/releases/vX.Y.Z.md`) from the first RC onward. Tag and `package.json` must always agree — `release.yml` fails the build otherwise. Full procedure: `.claude/skills/release-prep/SKILL.md`.

- [2026-06-14 slack file download](docs/findings/2026-06-14-slack-file-download.md) — `slack_download_file` needs `files:read`; no-access returns 200 + login HTML (not 403), guard on `text/html`; ctx.http OAuth branch has NO host guard, so the tool allowlists slack hosts before sending the Bearer and drops it on the presigned-CDN redirect hop
- [2026-06-14 ci pipeline triggers](docs/findings/2026-06-14-ci-pipeline-triggers.md) — trigger/poll/rerun/cancel for GitHub Actions (workflow_dispatch needs `on:`, returns 204 no run-id → poll), GitLab Pipelines (`variables` = `[{key,value}]`), Bitbucket Pipelines (trailing-slash POST, needs `pipeline`+`pipeline:write` scope → reconnect); github/gitlab no scope change
- [2026-06-18 apikey auth + New Relic](docs/findings/2026-06-18-apikey-auth-and-newrelic.md) — wired the previously-unused `apikey` auth path end-to-end (manifest `fields[]` w/ one `secret`, secret→token + rest→config, `ctx.http` sets `headerName` verbatim no Bearer, portal `ApiKeyAuthModal`); New Relic plugin = NerdGraph (region-scoped endpoint via `ctx.getConfig().region`); legacy alert-channel mutations are best-effort/untested
- [2026-08-03 bitbucket pr author reviewer bug](docs/findings/2026-08-03-bitbucket-pr-author-reviewer-bug.md) — `bitbucket_create_pr` fails silently when PR author included in reviewers; added validation to filter author, documented upsert behavior
- [2026-08-06 browser profile disk growth](docs/findings/2026-08-06-browser-profile-disk-growth.md) — persistent profiles filled 88% of the volume shared with `tokens.db` (2.9G of it duplicate Safe Browsing blocklists); nothing ever reclaimed them — a regression of the 2026-05-30 leak fix after profiles moved from tmpdir to per-user. Fix = disk-discipline spawn flags + cache trim on exit + `reapProfileDisk` sweep; storage-latency theory measured and refuted
- [2026-08-06 postgres dialect gotchas](docs/findings/2026-08-06-postgres-dialect-gotchas.md) — what a second SQL backend forces you to handle: BOOLEAN columns reject 1/0 on PostgreSQL, `?` is not always a placeholder (string literals, JSONB operators), a pooled connection breaks read-then-write atomicity (refresh-token rotation), schema init stops being an import side effect, and `tests/` was never type-checked
- [2026-08-18 browser navigate file-protocol SSRF](docs/findings/2026-08-18-browser-navigate-file-protocol-ssrf.md) — `browser_navigate` accepted non-http schemes; `file://` read local files through the shared session. Fix = explicit `http(s)`-only refine on the input schema
- [2026-09-02 connect link account mismatch](docs/findings/2026-09-02-connect-link-account-mismatch.md) — connect links trusted the bearer JWT alone; a human other than the minting user could complete the flow and store their own credential under that account (or, for cookie/browser links, get a live CDP handle). Fix = link is a claim not a capability; `POST /api/connect/redeem` gates on a matching portal session before any side effect runs, `GET /api/connect/session|browser-session` deleted
- [2026-09-04 oauth-authorize cross-origin cookie](docs/findings/2026-09-04-oauth-authorize-cross-origin-cookie.md) — resuming an agent-initiated `/authorize` for an already-signed-in human needs the login-CSRF binding cookie back; a portal fetch can't retrieve it (cookie is scoped to the server's own origin, invisible to Vite's dev proxy) — only a real top-level form POST to the server's own absolute origin does, and that origin must come from the portal's build-time config, never from the URL
- [2026-09-04 portal activity from the audit log](docs/findings/2026-09-04-portal-activity-from-audit-log.md) — every tool call has been writing an `audit_log` row all along with no endpoint reading it; exposing it needs an explicit `stored:false` for non-sqlite `AUDIT_LOG_DEST` (an empty table is otherwise indistinguishable from "nothing ran") and a longhand `created_at < ? OR (created_at = ? AND id < ?)` keyset predicate, because rows share a second and row-value comparison is not portable across both backends
- [2026-09-10 CDP live view over SSE + REST](docs/findings/2026-09-10-cdp-live-view-over-sse-rest.md) — portal live view dropped the raw CDP WebSocket for `attach`/`events`(SSE)/`commands`/`detach`; a WS can't carry an `Authorization` header, which is the only reason auth was ever an in-band frame; channelId is a handle not a credential, one stream owns a channel, input events batch at ~12ms, and no proxy needs to forward an Upgrade any more
- [2026-09-10 browser session pod affinity](docs/findings/2026-09-10-browser-session-pod-affinity.md) — the per-user chromium, `warmSessions`, `activeProfiles` and the live-view channel are all module-level maps, so every browser request must reach the owning process (a *worker* under `CLUSTER_ENABLED`, which no proxy can route inside); a second process on a shared profiles volume deletes the `SingletonLock` a live chromium holds. Fix = `attach` mints `HMAC(SESSION_SECRET, userId)` and starts nothing, the first `commands` starts chromium where the key routed it, and `X-Browser-Session` hashes every later request there (consistent hash, to pod endpoints — a ClusterIP behind it re-round-robins). Per-user not per-attach, or one user's two keys fight over one profile lock; it is a routing hint, not a credential — the bearer still authorizes and `cdpToken` retired
- [2026-09-11 REST tool execution endpoint](docs/findings/2026-09-11-rest-tool-execution-endpoint.md) — `POST /rest/:integration` runs plugin tools over plain JSON on the `/mcp` credentials and engine (the 60k cap was only ever in the MCP renderer); scoping a lenient body parser to it needs `removeContentTypeParser` first, because Fastify's exact-match `application/json`/`text/plain` parsers beat any regex one
- [2026-09-13 durable jot upload token](docs/findings/2026-09-13-stateless-jot-upload-token.md) — jot upload tokens lived in a module-level Map, so a restart voided them and `CLUSTER_ENABLED` broke uploads ~(N-1)/N of the time with a bare 404. Fix = a row in `pending_auth` under a `__jot_upload__` sentinel, **zero DDL**: despite the name it is the generic short-TTL handshake table (4 generic columns + nullable per-flow extras, keyed by `integration`), and `__oauth_authorize__` was already a non-auth ticket on it. Single use is now real — the `DELETE`, not the `SELECT`, arbitrates (`changes === 1`), atomic on both backends with no transaction — which a self-contained JWS/JWE token cannot do (per-process `jti` guard), besides leaking the owner id + scrypt hash into the URL and tripping find-my-way's 100-char `maxParamLength` with a 414
- [2026-09-15 CDP client dropped every event](docs/findings/2026-09-15-cdp-client-dropped-every-event.md) — `CdpClient` dispatched command replies and discarded every event frame (`if (typeof msg.id !== "number") return`), so the browser could be commanded but never observed; downloads also need a second client on the **browser** target (`Browser.setDownloadBehavior`/`Browser.download*`), and awaiting that second socket inside `ensureSession` turned session creation into something that could hang — routing is memoized and started in the background instead
- [2026-09-15 workspace path allowlist + abort race](docs/findings/2026-09-15-workspace-path-allowlist-and-abort-race.md) — `path.resolve` is string arithmetic, so a symlink inside the workspace passed the prefix check and still escaped (worst via `browser_upload_file`, which hands an absolute path to a browser that uploads it anywhere); split into `userFilePath` (create) vs `resolveExistingFile` (read, realpath'd — realpath the *base* too, `/tmp` is a symlink on macOS). Also: `createWriteStream` opens its fd asynchronously, so destroy-then-unlink can lose to the open and orphan a `.part-` file
- [2026-09-15 workspace inherited form parser](docs/findings/2026-09-15-workspace-inherited-form-parser.md) — `POST /api/files/:name` and presigned `PUT` committed 0-byte files with a 201 on `application/x-www-form-urlencoded` (curl `--data-binary` default): the workspace scope removed only the two built-in parsers, but a child scope inherits every app-level parser, and OAuth's exact-match form parser beat the `*` catch-all. Fix = `removeAllContentTypeParsers()`; test the raw-body scope on an app that carries the real boot's parsers
- [2026-09-16 browser session_id review](docs/findings/2026-09-16-browser-session-id-review.md) — after the routing key moved into tool args, `browser_expect_download`/`browser_await_download`/`browser_upload_file` had no `session_id` (never proxied → second chromium on the shared profile, download handle in the wrong process) and no handler verified the key it was given; both fixed. `session_id` = `HMAC(SESSION_SECRET, userId)`: a per-user routing key, not a session handle — one user, one chromium, one tab, no multi-session. Portal live view already carried `X-Browser-Session` on every request and dials the same page target the tools use. Added `browser_evaluate` (`page.evaluate` shape, `EVALUATION_FAILED`/`RESULT_TOO_LARGE`)
- [2026-09-16 test suite clobbered live sqlite](docs/findings/2026-09-16-test-suite-clobbered-live-sqlite.md) — a `vitest run` resolved the default `./data/tokens.db` against the repo root, which is also the compose bind mount for the live DB; DB suites open with `DELETE FROM users`, so the real SSO user (and its API key) vanished. Fix = `vitest.config.ts` pins `DATABASE_URL`/`WORKSPACE_DIR` to a per-process temp dir and `tests/db-isolation.test.ts` asserts the DB path is absolute and outside the repo. Recovery = re-insert the row with the original id + email (SSO links by sub, then email); the key must be re-minted
- [2026-09-17 connectors](docs/findings/2026-09-17-connectors.md) — per-user external MCP servers (HTTP streamable, OAuth 2.1): dynamic client registration from a base URL, per-user tool index parallel to the static plugin registry (`connectorName__tool`), no local arg validation (Claude Desktop parity), tokens reuse `connections` under `connector:<id>`; well-known OAuth paths are host-rooted; `encryption.ts` now computes its key lazily because a load-time `config` read broke config-mocked tests
- [2026-09-16 vault scrub over JSON text](docs/findings/2026-09-16-vault-scrub-json-text.md) — putting `{{vault:NAME}}` back by regexing the *text* of a stringified tool result can't tell a value position from string content: a scalar-looking secret echoed mid-sentence got a quoted placeholder injected, `JSON.parse` threw, and the `catch { return value }` fallback returned the **plaintext**; a short numeric secret also matched inside longer numbers. Fix = structural walk over the JSON-normalised value (strings via `scrubString`, scalar leaves by strict `String(leaf) === value`, keys too), no parse step and no fallback — an unserialisable result throws `VaultScrubError` → `VAULT_SCRUB_FAILED`. Residual: canonicalisation (`"5432.0"` → `5432` after `z.coerce.number()`)
